# User flow — Cockpit

## Modelo conceptual

⬜ TODO — se define tras la inmersión.

Lo que ya está acotado por contrato, y condiciona cualquier flujo que dibujemos:

- El cockpit **informa y responde**. No propone flujos accionables ni ejecuta nada en los sistemas
  de origen.
- **No hay bandeja de acciones y decisiones**, porque requeriría que alguien mantuviera estado y
  bloqueadores, y en este alcance no hay backoffice.
- El colaborador **no configura** sus KPIs ni sus alertas desde la herramienta.

De ahí sale la pregunta de producto más importante que tenemos abierta: **qué ve el eMerchant al
abrir el cockpit**, si lo primero no puede ser una lista de cosas que hacer.
